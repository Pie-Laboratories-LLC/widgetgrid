# Svg Parsing

An important aspect of Anonyme is text rendering.  The apis, open gl and vulkan
are not simple.  Then there's this barrier - there's no way to render text.  Not
that there should be.  And at this point, there are many alternatives, most
notably imgui which solves two problems - the ability to render text and to
create a user interface.

As a personal project, I wanted to do the text rendering myself.  Text rendering
is interesting in its own right, but what's the point of rendering text if you
can't render poo emojis?  Emojis (and other interesting symbols) are
predeominantly implemented as svgs.  So hence, svg parsing is the core of the
GUI engine I am building.

I released the svg parser separate from the main project with c# bindings.  I
did this originally because there just weren't many options in c# for svg
parsers.  Now there is more variety.  The svg parser has enabled a number of
other little projects.

The svg parser is written in c++.  c++ doesn't natively support cross platform
compilation: e.g., c++ is compiled into an intermediate object file format which
is different from platform to platform, and indeed can even vary from one
computer to another.  So to provide c# bindings it's necessary to supply
versions of the library compiled for different platforms.  When I initially
released the svg parser, I only released windows and linux versions.

Separately, Pie Laboratories' corporate logo is an svg.  A core goal is to be
able to render it in 3d.  To that end I've added support for `<text>` and
`<imsge>` nodes.

So the new release of the svg parser uses github actions to compile for windows,
linux, and macOs (ARM).  As noted, this supports `<text>` and `<image>`
entities.  This is version 1.1.0 and is available on
[GitHub](https://github.com/Pie-Laboratories-LLC) and
[NuGet.org](https://www.nuget.org/profiles/PieLaboratoriesLLC).
