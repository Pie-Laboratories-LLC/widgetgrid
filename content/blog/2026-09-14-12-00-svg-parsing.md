# Svg Parsing

One of the goals of the Anonyme project is to allow me to implement a user
interface in 3d, i.e., a true 3d ui where the windows are part of the scene.  In
order to do that, I need to be able to render text; what's more, I have to be
able to render poo emojis 💩 and possibly others, but mainly 💩.

I developed a 2d rendering library and the 2d rendering library is responsible
for rendering text.  I could've gone the bitmap fonts route which would save a
lot of complexity and real work, but opted for the challenge of rendering text,
including emojis.  I am also intrigued by the idea of moving this to the gpu,
eventually.

Many emoji fonts are OT-SVG fonts - i.e., the glyphs are svg documents.  This is
the genesis of an Svg Parser I've developed.  It's a simple project that
produces an abstract syntax tree from a simple svg.  It's not yet a full-fledged
svg parser, but that will expand over time.  The corporate logo is an svg with
embedded images and text, so most recently I've updated the Svg Parser library
to include support for `<text>` and `<image>` entities.

One of the original reasons I started the Svg Parser project was that there
weren't many viable open source alternatives to c#.  As mentioned elsewhere, I
ported work on Anonyme from c# to c++, but I still wanted to release the Svg
Parser with c# bindings.

The complication with bindings against a c++ library is different platforms -
linux, windows, and macOS.  With this update I included a github workflow that
builds the c++ library for the three platforms.  Claude talked me out of more
aggressive support Solaris, HP/UX, VMS, and os/360 support.  He pointed out that
github actions didn't have support for some of these platforms.  I feel like
that's a real strike against github actions, so alas to consumers of my Svg
Parser who are VMS partisans will simply have to build the library for
themselves.
